# 3.1 Abordagem de Desenvolvimento

O PetAgenda é desenvolvido de forma **iterativa e incremental**. Cada ciclo produz uma seção deste documento, na ordem exigida pela análise de sistemas. Primeiro define-se o que o sistema é (4.1). Depois vêm os requisitos e casos de uso (4.2.1 e 4.2.2), seguidos da estrutura de classes (4.2.3), comportamentos e sequências (4.2.4 e 4.2.5), modelo de dados (4.2.6) e protótipo de telas (4.2.7). A arquitetura (3.3) fecha o documento.

Ao final de cada ciclo, a nova seção é conferida contra as anteriores. Todo caso de uso precisa ter vindo de um requisito, e toda classe precisa aparecer em algum fluxo do sistema. Se houver divergência, a correção é feita na origem e a nova versão é salva no repositório GitHub.

Essa abordagem foi escolhida porque permite revisar cada parte do projeto com a cliente antes da etapa seguinte, evitando que erros de entendimento acumulem até o final do documento (como ocorreria no modelo em cascata). Como o desenvolvimento é individual, as cerimônias do Scrum (como reuniões diárias) ficam de fora, mantendo-se a ideia central de ciclos curtos com entregas revisáveis.
